Healthcare Product Planning & QA

트라이업수개월간 멈춰 있던 의료급여 기능을 업무분석부터 실환경 검증까지 구체화하였습니다

비급여 피부·미용 시장에 특화된 CRM을 중심으로, 접수와 진료를 지원하는 EMR 기능이 결합된 서비스에서 고객지원, 사용자 교육, 오류점검과 문서화를 담당하였습니다. 신규 의료기관의 오픈 현장과 학회 부스행사에도 참여하여 실제 운영과 현장 응대를 지원하였습니다. 병원 원무와 청구 경험을 바탕으로 제품에 없던 의료급여 환자 진료지원 기능의 업무 흐름을 설계하고, 기능·화면 정의와 QA 문서 작성, 테스트 병원 섭외 및 실환경 검증까지 수행하였습니다.

Project Overview

현장경험으로 업무의 기본 구조를 세우고,제품에 없던 의료급여 기능을 실제 사용 단계까지 연결했습니다

도입을 검토하던 병원의 요구가 있었지만 의료급여 업무를 아는 내부 인력이 없어 기능 개발과 병원 도입이 수개월간 진행되지 못하고 있었습니다.

제품의 중심은 비급여 피부·미용 의료기관의 고객관리를 위한 CRM이었으며, EMR은 접수와 진료업무를 지원하는 보조 기능에 가까웠습니다. 건강보험 환자의 자격정보는 조회할 수 있었지만 의료급여 환자는 대상 여부만 확인하는 수준이었고, 자격조회 이후 접수, 진료, 진료확인번호 처리, 건강생활유지비 사용, 수납과 청구를 연결하는 기능은 마련되어 있지 않았습니다.

제품 도입을 검토하던 의료기관은 의료급여 환자의 접수·수납·청구까지 처리할 수 있어야 한다고 요청하였습니다. 그러나 회사 안에는 해당 제도와 병원 업무를 아는 인력이 없어 요구사항이 구체화되지 못했고, 병원 도입도 수개월간 지연되고 있었습니다.

병원 원무와 청구 경험을 바탕으로 의료급여 환자가 내원한 시점부터 청구 전까지 필요한 전체 업무를 정리하였습니다. 공개된 자격조회 API 자료와 요양기관정보마당의 실제 처리방식을 확인하고, 사용자 화면과 기능 동작, 예외상황과 테스트 방법을 문서로 구체화하였습니다.

단순히 기능을 제안한 것이 아니라, 제도 확인부터 업무 흐름·화면·예외조건·QA·실환경 검증까지 제품이 실제로 사용되기 위한 전체 과정을 담당하였습니다.
DISCOVER

문제 확인

병원 도입을 막고 있던 의료급여 처리 공백과 내부 지식 부족을 확인하였습니다.

RESEARCH

제도 분석

공개 API 문서와 기관 시스템에서 자격조회 및 승인 처리기준을 확인하였습니다.

DEFINE

기능·화면 정의

업무 흐름, 사용자 노출정보, 상태별 동작과 예외조건을 문서화하였습니다.

TEST

QA 설계

정상·오류·취소·재승인 상황을 포함한 테스트 시나리오를 작성하였습니다.

VALIDATE

실환경 검증

테스트 병원을 직접 섭외하고 실제 의료기관 환경에서 기능을 확인하였습니다.

01 · Service Operations

사용자 교육과 오류 대응을 수행하고,반복되는 문의를 제품과 문서의 개선으로 연결했습니다

01

고객지원

전화, 원격과 채널톡을 통해 사용자의 기능 문의에 답하고 실제 환경의 오류를 진단하였습니다.

02

사용자 교육

신규 고객의 초기 설정을 지원하고, 접수부터 진료와 수납까지 기능별 사용방법을 교육하였습니다.

03

오픈 현장지원

신규 의료기관의 오픈 현장에 방문하여 실제 접수·진료·수납 흐름을 확인하고 문의와 오류에 대응하였습니다.

04

학회 부스지원

학회 부스행사에 참여하여 부스 운영과 방문자 현장 응대를 지원하였습니다.

05

요구사항 전달

사용자의 요청을 업무 흐름, 조건과 기대결과로 정리하여 개발팀이 검토할 수 있도록 전달하였습니다.

06

매뉴얼·FAQ

반복 문의와 업데이트 기능을 FAQ, 사용자 매뉴얼과 가이드로 작성하고 지속적으로 갱신하였습니다.

02 · Problem Definition

‘의료급여 환자도 처리되게 해 달라’는 요구를,개발 가능한 전체 업무 흐름으로 구체화하였습니다

도입이 지연된 이유

병원이 원한 것은 단순히 자격조회 화면에 의료급여 여부를 표시하는 기능이 아니었습니다. 의료급여 환자를 접수하고 진료기록을 작성한 뒤 진료확인번호를 처리하고, 건강생활유지비를 사용하여 수납과 청구까지 이어갈 수 있어야 했습니다.

기존 제품은 비급여 피부·미용 CRM에 특화되어 있었고 EMR 기능은 보조적인 범위로 구성되어 있었습니다. 건강보험 자격조회는 가능했지만 의료급여는 대상 여부만 확인하고 있었으며, 회사 내부에도 의료급여 환자의 실제 원무·청구 흐름을 설명할 인력이 없었습니다. 이 때문에 요구가 접수된 뒤에도 개발범위와 화면동작을 정하지 못한 상태였습니다.

저는 병원에서 수행했던 원무와 청구 경험을 바탕으로 먼저 업무의 기본 틀을 잡고, 제도 자료와 외부 시스템을 확인하면서 기능요건을 단계적으로 구체화하였습니다.

BEFORE 의료급여 여부만 확인하고
후속 업무는 처리할 수 없는 상태
  • 상세 자격정보 부족
  • 진료확인번호 처리기능 부재
  • 건강생활유지비 사용 불가
  • 접수·진료·수납·청구 연결 부재
  • 요구사항을 정의할 내부 경험 부족

03 · Policy & Workflow Analysis

자격조회 API와 기관 시스템을 확인하고,접수부터 수납·청구까지 끊기지 않는 흐름을 설계했습니다

의료급여 업무의 처리순서와 건강보험 자격조회와는 다른 예외상황을 먼저 정리한 뒤, CRM 중심의 기존 제품에 추가해야 할 데이터와 EMR 기능을 도출하였습니다.

심평원에 공개된 자격조회 API 문서를 찾아 의료급여 자격조회 시 전달되는 항목과 응답구조를 확인하였습니다. 제품이 기존에 사용하던 건강보험 조회방식과 비교하여 의료급여 환자에게 추가로 필요한 정보와 처리범위를 정리하였습니다.

요양기관정보마당에서는 정상 자격조회뿐 아니라 오류가 발생했을 때 어떤 정보와 상태가 반환되는지 확인하였습니다. 진료확인번호의 승인·취소·재승인 처리와 건강생활유지비의 조회 및 사용방식도 실제 업무 순서에 맞춰 분석하였습니다.

확인한 내용을 바탕으로 의료급여 자격조회, 접수, 진료기록 작성, 진료확인번호 처리, 건강생활유지비 사용, 수납과 청구가 하나의 환자정보를 기준으로 이어지도록 전체 기능 흐름을 설계하였습니다.

STEP 01

자격조회

의료급여 종별과 기관정보 등 접수에 필요한 자격정보 확인

STEP 02

접수·진료

조회된 의료급여 정보를 접수와 진료기록에 연결

STEP 03

진료확인번호

승인·취소·재승인에 따른 번호와 상태 변경 처리

STEP 04

수납·청구

건강생활유지비 사용과 환자부담금 및 청구정보 반영

04 · Feature & Screen Definition

기능이 있다는 수준을 넘어,사용자에게 무엇을 보여주고 어떻게 동작할지 정의했습니다

기능 정의

업무 단계마다 필요한 데이터와 기능이 이어지도록 처리조건을 정리하였습니다.

  • 의료급여 자격조회와 환자 접수 연결
  • 진료기록 작성 후 진료확인번호 승인
  • 승인 취소와 재승인 처리
  • 건강생활유지비 조회와 사용
  • 수납과 청구에 필요한 정보 전달

사용자 화면 정의

조회 결과를 그대로 노출하지 않고 실제 사용자가 판단하고 처리하는 데 필요한 정보만 구분하였습니다.

  • 화면에 보여줄 정보와 감출 정보 구분
  • 정상 조회와 오류응답의 상태 표시
  • 승인·취소·재승인 버튼과 동작조건
  • 건강생활유지비 사용 전후 화면상태
  • 접수·진료·수납 화면의 정보 연계

05 · QA & Field Validation

테스트 기준을 직접 작성하고,실제 의료기관을 섭외해 현장에서 기능을 검증했습니다

FROM DEFINITION TO FIELD

문서에서 끝내지 않은 실환경 검증

정상 처리와 예외상황을 구분하여 의료급여 자격조회, 오류응답, 진료확인번호 승인상태와 건강생활유지비 사용에 대한 테스트 시나리오를 작성하였습니다. 개발된 기능이 정의한 내용과 다르게 작동하는 부분은 화면과 조건별로 정리하여 수정결과를 다시 확인하였습니다.

의료급여 기능은 실제 자격정보와 기관환경에서 확인해야 하는 항목이 있었기 때문에 테스트에 참여할 의료기관을 직접 섭외하였습니다. 해당 병원에서 자격조회와 후속 기능을 검증하고, 실환경에서 확인된 문제를 개발팀에 전달하여 개선하였습니다.

수개월간 구체화되지 못했던 요구를 제도분석, 기능·화면 정의, QA 문서, 테스트 병원 섭외와 실환경 검증까지 이어지는 실행과제로 전환하였습니다.

QA 01

정상 흐름

자격조회부터 승인, 건강생활유지비 사용과 수납까지 전체 처리결과를 확인하였습니다.

QA 02

예외 흐름

조회 실패, 오류응답, 승인 취소와 재승인 등 상태별 화면과 동작을 검증하였습니다.

QA 03

실환경 검증

테스트 병원을 직접 섭외하고 실제 기관정보와 사용자 업무에서 기능을 확인하였습니다.

06 · Additional Product Work

의료급여 기능 외에도 현장경험을 활용해,진료기록과 마약류 관련 기능의 개선에 참여했습니다

진료실 진료기록 고도화

의료진이 실제로 진료기록을 작성하는 순서와 사용성을 검토하고 기능 고도화 기획에 참여하였습니다.

마약류 기능 개선

의료기관에서 마약류 관련 업무를 처리하는 과정과 현장 요구사항을 분석하여 개선 기획에 참여하였습니다.

사용자 문서 업데이트

신규·개선 기능을 사용자가 실제 업무에 적용할 수 있도록 FAQ, 매뉴얼과 안내자료를 작성하고 갱신하였습니다.

Core Contribution

병원 업무를 아는 사람이 없어서 멈춰 있던 요구를,
개발하고 검증할 수 있는 제품 과제로 전환하였습니다.

원무와 청구 경험을 바탕으로 의료급여 제도를 제품의 데이터와 화면, 기능 흐름으로 바꾸었습니다. 사용자 요구를 전달하는 데 그치지 않고 기능정의서와 화면 정의, QA 시나리오, 테스트 기관 섭외와 실환경 검증까지 수행하며 현장과 개발을 연결하였습니다.
